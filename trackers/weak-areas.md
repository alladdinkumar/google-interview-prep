## How to Use This Tracker

1. **During daily logs:** when you flag "Misses" → "Got stuck on graph DFS", you append a row here with source = "daily log YYYY-MM-DD".
2. **During weekly reviews:** scan this tracker. If 3+ items in same topic, that's the focus for next week's PM theory sessions.
3. **During monthly reviews:** items active >4 weeks → escalate (extend the phase, allocate dedicated remediation block).
4. **Before each mock:** glance here. Don't go into a mock with 5+ items in the mock's domain.
5. **End of Phase 5:** every active item should either be remediated or explicitly *accepted as residual risk* — i.e., you've decided not to fix it before applying.

---

## Remediation Patterns That Work

- **For a DSA topic:** 3 new problems of that pattern, then re-attempt the original problem that flagged it
- **For an HLD case study:** re-walk it without notes, then explain it out loud to an empty room
- **For an LLD pattern:** re-draw the class diagram from scratch, then code the key class
- **For a behavioral story:** re-rehearse on camera, watch back, fix one thing
- **For a CN/OS/DBMS concept:** find a 6-min video, watch, then write a one-paragraph explainer in your own words

---

## Remediation Patterns That Don't Work

- Re-reading the same notes (passive intake doesn't fix gaps)
- "I'll come back to it later" without a target date
- Adding 10 problems to a "to-do list" you never start

If a weak area sits for 2+ weeks with no remediation attempt, it's flagging that you're either avoiding it or it's the wrong topic to fix right now. Decide consciously: address or defer with reason.
